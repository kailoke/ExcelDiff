# AI Agent 工作协议

> 引用约定（本文件的编号一律按台账名读写，不在此逐条展开）：`ADR-###` = `DECISION_LOG.md` 的架构决策条目；`R-###` = `RISK_REGISTER.md` 的未关闭风险；`§N` = 本文件章节号（跨文件引用时写明文件名）。

> 本文件只保留**操作程序**；硬护栏与读取集正典 = 根 `AGENTS.md`；工程硬约束清单 = `AI_docs/INVARIANTS.md`（A–F 六区，改动前逐条核对）。

## 0. 开始工作前

**主会话（编排/验收）：**

1. 跑 `.\AI_Script\session-brief.ps1` 拿简报（git 摘要 + 范围/锚点健康 + 活跃任务）。
2. 开工前运行 `.\AI_Script\verify-scope.ps1`，确认 SCOPE/ANCHORS 健康（工作区常带他人修改，只处理本任务相关文件）。
3. 按任务取 `AI_docs/ROUTING.md` 对应行；**仅真正可并行且值得的任务才派发**（判定见 `ORCHESTRATION/MODEL_ROUTING.md` §3 派发纪律），线性任务由主会话直接实施。

**子任务（执行派发单）：**

1. 按派发单锚点直达代码入口，读代码确认控制点，不根据文件名猜测行为。
2. 第一次编辑前写出一个可证伪的局部假设和一个最便宜的验证方式。
3. 完成后只按派发单 §G/§H 回写与交回，不扩大范围。

## 1. 实施规则

- 只处理当前任务和直接依赖，不顺手重构无关模块。
- 优先复用项目现有模式：Prism `BindableBase`、`Setting<T>` 设置类、`LocalizationManager` 字符串桥、程序集名派生规则。
- **单一版本**（ADR-019）：不为"另一个变体"留条件编译或手工构建分支；读取层只有 ExcelDataReader 一条实现。
- 不修改用户的权威数据（外部 xlsx 数据仓、用户 git 配置里的 `[difftool "ExcelDiff"]` 标签），除非用户明确授权。
- 信息不足时写入状态或风险台账；不要自行编造。
- 死代码的去留只以"当前版本是否需要"判定：删除先关入口、替代方案验收后再删；不为"将来可能重启"保留死分支（ADR-019 的做法：确认无调用方后整体删除，不留兼容别名）。
- 每次代码编辑后立即执行最窄的可行验证；改动完成后跑 `.\AI_Script\verify.ps1` 全绿（含 NetDiff 31 用例与 lang 同步）。
- 验收只做关键性项（能证明该功能成立的最小项），人工验收统一排最后阶段。
- **注释自查**：新增/改动的注释只允许三类——关键逻辑、核心问题（防错/时序/幂等的"为什么"）、反复犯错处（一句话坑记录）；判据 = 删掉这条注释，下一个读者会不会困惑；不会就删。本工程口径：不主动添加注释，改动遵循既有代码风格（net472 老式 C#：无 nullable、无 target-typed new、无文件级 namespace；命名空间 = 目录名）。
- 编辑他人 lock 的文件前，先在 `EXECUTION_PLAN.md` §8（当前切片队列）队列行认领（lock 见 `MODULE_REGISTER.md`）。
- 动 IPC/生命周期/读取层/安装器事务/本地化管线之前，先核对 `INVARIANTS.md` 对应区（C/B/E/D）。

## 2. 重复性操作固化为脚本（AI_Script）

任何会被第二个会话重复执行的命令/步骤，一律固化为脚本放入 `AI_Script/`。**脚本清单与触发时机唯一出处 = `AI_Script/README.md`**（此处不重复枚举）。机器相关路径一律出自根目录 `ProjectPaths.ps1`（路径单一事实源，`-Print` 自查），脚本与文档不写盘符。

## 3. 引用与表达纪律

正文（锚点写法 / 注册表 / 刷新 / 门禁通道 / 对用户与策划的输出规范）= 根 `AGENTS.md`「引用与表达纪律」；本节不重复。

## 4. 回复前自查（每轮必做；规则本体 = 根 `AGENTS.md`「引用自带解释」）

给用户/业主的正文（每轮对话、交付文本、派发单、交接件）**发出前**按三步走：

1. **列号**：把本轮将出现的编号与术语过一遍——`ADR-###`（决策）/ `R-###`（风险）/ 切片与任务编号 / 章节号 `§N` / 文件名与脚本名 / 配置参数名与代码符号。
2. **补解释（四组机械扫描；草稿写完即逐组过一遍正文，禁止以"我懂规则"代替扫描）**：命中**首次**出现且同行、同括号内没有一句人话解释 ⇒ 就地补"它是什么"（文件类还要给标题 + 打开看哪节），或删掉该词改用平实描述。四组按**结构特征**判定，不需要维护任何术语表：

   | 组 | 扫什么（结构特征） | 补齐要求 |
   |---|---|---|
   | 编号 | `ADR-###` / `R-###` / 切片号 / `§` 等 | 首次出现带一句人话，或删号直说。同族的每个具体条目号各算一处引用 |
   | 路径与文件 | 含 `/` 或带 `.md`/`.ps1`/`.cs`/`.json` 等后缀的 token | 标题 + 一句它是干什么的 + 打开看哪节 |
   | 英文缩写与代码符号 | ≥2 字母全大写缩写（如 IPC、ARP、COM）、方法/类/字段名、配置参数名 | 参数名带功能名/显示名；代码符号带一句作用 |
   | 中文黑话 | 做替换测试：心里把该词换成日常说法，句子仍成立 ⇒ 合规 | 首次出现就地补一句人话 |

   判据 = 一个没参与过本项目讨论的人，只读本轮正文，能否明白说的是哪件事。
3. **跑工具**：草稿写进临时文件 → `.\AI_Script\lint-reply.ps1 -Path <草稿文件>`（或 `-Text`、管道）；命中（exit 1）就逐条补齐再重跑。

> 为什么必须自己跑、不能指望机器兜底：`AI_Script/lint-docs.ps1` 的 E14/E15（引用无解释检查，命中即拦）**只扫文件**（`AGENTS.md`、`AI_docs/**`、`.agents/**`），**扫不到对话回复** ⇒ 回复侧没有自动门禁，这一步是纪律不是可选项。承载这条纪律的三处 = 根 `AGENTS.md` 的「发前自查」硬步骤 + 本节三步 + 完成时回写的「引用解释自查」字段；工具 = `AI_Script/lint-reply.ps1`。

## 5. 完成时必须回写

回写目标与单一事实源映射见 `AI_docs/README.md`「回写规则」；完整交接写 `AI_docs/HANDOFFS/<yyyy-MM-dd>-<task-id>.md`；交付前跑 `verify-scope.ps1`（SCOPE/ANCHORS/LINT 必须 PASS）。**新增/更新台账条目时先自问：这条在下一个任务里会被读到吗？不会 → 不写**（历史归 git log；本判据只筛新增内容，不免除回写义务）。最终回复按四项定式：

```text
完成内容：
变更文件：
验证命令/场景：
验证结果：
引用解释自查：（必填：四组机械扫描已逐组过完 + lint-reply.ps1 输出结果；正文无编号时可只写"四组扫描已过，无编号未跑工具"）
未完成或阻塞：
新增风险：
是否需要新增决策：
Git 提交溯源：Task: <任务 ID>（git log --grep 定位；台账与代码同笔提交，不写自引用 ID）
```

## 6. 决策纪律

以下事项必须写入 `DECISION_LOG.md` 的**当前有效条目**（只留当前有效条目，不留历史）：

- 运行模式和核心架构变化（程序集名/派生规则/安装链形态）。
- 数据格式、读取实现、写路径入口与兼容策略。
- 关键语义的权威源归属（哪份文件/哪个注册表键说了算）。
- 功能范围取舍与系统删留。
- 任何会影响后续多个模块的接口选择。

## 7. 状态值规范

`未开始` / `盘点中` / `开发中` / `验证中` / `待入库`（验收已过，等待提交）/ `完成`（已入库后即出队）/ `阻塞` / `降级`。

## 8. Git 提交与追踪

> 两层事实源：Git = 历史唯一来源（版本/顺序/差异/回滚）；`AI_docs/` = 当前状态/任务/决策/风险。台账只写当前口径，历史查 git log。

- 仓库：根目录单仓。受限环境里 git 若报"非安全目录"，按提示加 `-c safe.directory=<仓库路径>`。
- 提交粒度：一个提交一个完整意图，不混入无关格式化、他人修改、未验证半成品、不同模块决策。
- 提交消息：`<type>(<scope>): <intent>` + `Task / Status / Decision / Risk / Verify` 五行（`Task:` 供 `git log --grep "Task: <ID>"` 溯源）。
- **提交授权（本工程硬规则）**：**AI 不直接 commit**。改动完成后给出 Commit subject / description 供审查，实际提交由用户决定并执行；"提交"只授权到本地提交为止，**推送（`git push` 及任何写远端的操作）在用户当轮明确指令前永不执行**，二者需分别取得指令。机械防线 = `.githooks/pre-push` 推送闸门（失败关闭；一次性豁免变量 `EXCELDIFF_ALLOW_PUSH`，**AI 会话不得设置该变量、也不得用 `--no-verify` 绕过**）。
- **台账先行**：先写 `PROJECT_STATUS.md` 与 `EXECUTION_PLAN.md` §8 队列，与代码**同一笔**提交（`.githooks/pre-commit` → `pre-commit-check.ps1` 强制同笔，未暂存即拒提）；不写本次提交的 commit ID（自引用悖论），关联靠 `Task:` 行。
- **出队即删交接件**：切片完成并出队时，其 `HANDOFFS/<yyyy-MM-dd>-<task-id>.md` 一并删除（活跃件才留）。
- 提交前：`git status --short` / `git diff --check` / `git diff --stat` 复核；钩子自动跑禁改区拦截 + 锚点健康 + CODE_INDEX 重暂存 + 台账同笔 + 文档 lint。
- 提交后：`git show --stat HEAD` 确认范围；架构/范围变化写 `DECISION_LOG.md`。
- 未提交工作：先读 `git status`；不重置/覆盖他人修改；不把用户修改记为自己完成；交接里区分"已提交/未提交/未验证"。
- 回滚排查：`git log --all -- <path>` / `git log -S"<sym>"` / `git blame`；禁用 `reset --hard`/`checkout --` 作默认修复手段。
- 历史与台账不一致：以当前代码与可复现验证为准，直接覆盖台账。
