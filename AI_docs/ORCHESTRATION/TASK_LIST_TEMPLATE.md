# TASK_LIST_TEMPLATE（子任务派发单模板）

> 引用约定（本文件的编号一律按台账名读写，不在此逐条展开）：`ADR-###` = `DECISION_LOG.md` 的架构决策条目；`R-###` = `RISK_REGISTER.md` 的未关闭风险；`§N` = 本文件章节号。

> 用法：**先过派发判定**——仅真正可并行且值得的任务才派发（规则见 `MODEL_ROUTING.md` §3），线性任务由主会话直接实施。派发时主会话复制下方模板整段填写后发给子会话/子代理。**低消耗模型必须内联 dossier 与锚点材料**（§C 必填）；强模型可只给锚点让它自查。
> 一份派发单 = 一个可验收的切片。填不完 §F 就不要派发。

---

```markdown
# task list <task-id>（绑定 `EXECUTION_PLAN.md` §8 切片，如 N3.2）

## A. 档位与角色
- 档位：强 / 省（判定依据见 ORCHESTRATION/MODEL_ROUTING.md §2，一句话说明为什么）
- **派发闸门（`MODEL_ROUTING.md` §3 的并行判定，必填实答、不是勾选）**：
  - Q1 主会话在此子任务运行期间并行做：<具体另一件工作；写"等待/无"即触发弃单>
  - Q2 并行的收益：<压下的总时长或质量提升，一句话>
- 角色：实现 / 调研 / 修复 / 验证
- 前置依赖决策：<ADR-### 编号，无则写"无">

## B. 目标（可证伪）
- 一句话目标：
- 完成判据：<可观察的行为/输出，不写"做好优化"这类不可判词>

## C. 事实与材料（低消耗模型必填，强模型可从简）
- 已知事实（来自 ARCHITECTURE.md / dossier / PROJECT_STATUS）：
  - <逐条列出，注明来源>
- 入口锚点：
  - `路径/File.cs <!-- anchor:锚点ID -->` —— <一句话说明>
- 内联 dossier：<优先内联**事实摘要**（≤3KB）——只列子任务必须知道的事实；仅当任务是对该模块深改、且摘要不足以承载语义时，才整段粘贴 `AI_docs/DOSSIER/<模块>.md`（≤8KB）>

## D. 范围与不变量（三块 + 一行机读范围，缺一即打回）
- **机读范围**（供 `AI_Script/verify-scope.ps1 -TaskBrief <本单路径>` 机器校验，必须与下面①逐字一致）：
  `SCOPE: <glob>[;<glob>...]`
- **① 独占文件面（必填，并写一句"为什么是这几处"）**
  - 本单可改：<glob 列表，如 `ExcelDiff.GUI/Views/**`>
  - 为什么是这几处：<另一件并行工作正占用哪批文件，或本单为什么必须碰它>。这是**分工边界**（同一时间只允许一个写者），不是实现指引——执行者从仓库里推不出"此刻别人在改什么"。
- **② 本任务额外禁止（禁改区不在此复述）**
  - 禁改区唯一正典 = 根 `AGENTS.md`（每个会话自动加载）；本单不重复全表。
  - 本任务额外禁止：<glob 或"无">；因为 <一句原因>。
- **③ 必须满足的不变量 + 卡住时的出口**
  - 不变量：<写成"必须满足 P，因为 Q"，不要只写"不许 X"；贴近读取层/IPC/安装链时逐条指出对应 INVARIANTS 区>
  - **出口（本段逐字保留）**：若按上面的范围或不变量做不通，**停下回报主会话**，由主会话决定"扩范围"还是"改由主会话自己实施"；**不得自行扩大范围，也不得绕开约束另找实现位置**。回报只需三句：想做什么 / 卡在哪条 / 需要什么——不必先动手。

## E. 步骤（省档模型必填到命令级）
1. <步骤，含要跑的命令>
2. ...

## F. 验收（命令级，主会话将逐条执行）
- [ ] `.\AI_Script\verify-scope.ps1 -Compile -TaskBrief <本单路径>` → SCOPE PASS / **TASK SCOPE PASS** / ANCHORS 0 unresolved / LINT 0 error / 编译腿 exit 0
- [ ] <任务专属验收命令或静态核对点>
- [ ] 人工路径：<向导/模态弹窗等脚本点不了的交互怎么点、预期看到什么；无法在本轮执行则标注"未验证风险">

## G. 回写要求（完成后执行）
- `AI_docs/PROJECT_STATUS.md`：<该改哪几行>
- `AI_docs/EXECUTION_PLAN.md` §8：更新队列行（状态 + 交接文件）
- `AI_docs/HANDOFFS/<yyyy-MM-dd>-<task-id>.md`：按本模板 §B/§F/§H 收尾
- `AI_Script/refresh-code-index.ps1` 已运行；新增锚点已进 `AI_Script/code-anchors.json`
- DECISION_LOG / RISK_REGISTER / MODULE_REGISTER：<需要则写明条目>

## H. 交付报告格式
完成内容 / 变更文件 / 验证命令与结果 / 未完成或阻塞 / 新增风险 / 是否需要新增决策 / Git 提交溯源（Task: <任务 ID>，提交纪律见 `AGENT_WORK_PROTOCOL.md`「Git 提交与追踪」：AI 不直接 commit）
```

## 填写红线

1. §D 的机读 `SCOPE:` 行与①的 glob 必须逐字一致、不能写"全部"；收货时用 `verify-scope.ps1 -TaskBrief <本单>` 机器校验"改动 ⊆ 本单范围 ∪ 台账面"（台账面 = `AI_docs/**`、`AI_Script/code-anchors.json`），越界即 FAIL。**派发时必须先写基线**：`verify-scope.ps1 -TaskBrief <本单> -WriteScopeBaseline`（把当时工作区**已有**的改动路径记进 `<本单>.scope-baseline`，与该单同目录、已 gitignore）。共工作区下不写基线，别的会话的在飞改动会被判成本单越界。
2. §D 的三块缺一即打回：① 独占文件面（含"为什么"）② 本任务额外禁止 ③ 不变量 + 出口条款。**禁止把"判断"压成一句没有理由的禁令**——执行者做不通时只有"硬做"和"绕开"两条坏路。
3. §F 至少含 verify-scope 一条；纯调研任务可豁免编译腿但必须豁免理由。
4. 不确定的事实**不要编造**：写"待确认"并转为主会话调研项，或升档强模型先调研再派发。
5. 省档模型的派发单，§C 与 §E 缺一即打回重填，不带病开工。
6. **§A 派发闸门两问任一无实答（或 Q1 写"等待/无"）⇒ 本单作废，任务转主会话直接实施**——派发不是默认动作，并行才是唯一理由（`MODEL_ROUTING.md` §3）。
