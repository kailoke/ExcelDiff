# MODEL_ROUTING（模型档位路由与会话编排）

> 引用约定（本文件的编号一律按台账名读写，不在此逐条展开）：`ADR-###` = `DECISION_LOG.md` 的架构决策条目；`R-###` = `RISK_REGISTER.md` 的未关闭风险；`§N` = 本文件章节号。

> 定位：主会话编排纪律，**补充**（不覆盖）`AI_docs/AGENT_WORK_PROTOCOL.md`；冲突时以协议与 `DECISION_LOG.md` 为准。
> 背景假设：主会话 = 强能力高消耗模型，做**编排、派发、交叉验收、质量管理**，并**直接实施串行任务**；仅可并行的任务派发子任务。也适用于手动开的多个并行会话。

## 1. 角色分工

- **主会话（强模型）**：解析任务 → 定边界与锚点 → **线性/串行任务直接实施；仅真正可并行且值得的任务才派发**（判定见 §3）→ 验收（跑门禁、对账验收标准）→ 回写台账。
- **子任务（按档位）**：执行派发单，完成后按「回写要求」交回。子任务**不得**超出派发单的独占文件面，不得自行扩大范围；按派发单 D 节的不变量做不通时，**停下回报**（三句：想做什么 / 卡在哪条 / 需要什么），由主会话决定"扩范围"还是"改由主会话自己实施"——**不得绕开约束另找实现位置**。

## 2. 档位判定规则

**用强模型（逻辑推理/架构设计）**，满足任一条：

- 触碰 `INVARIANTS.md` 高危区：B 读取层（行列语义、扩展名分发）、C 生命周期/IPC（常驻、命名管道、事件分发器）、E 安装链（卸载事务、归属闸门、注册表）、D 本地化管线（resx/lang 解析顺序）。
- 跨模块接口设计、新模块骨架、启动链/装配层改动。
- 根因不明的 bug（需提出可证伪假设）、并发/时序问题（`Task.Run` 读取、管道线程、模态交互）。
- 需要在多个候选方案间做架构取舍（先开 `DECISION_LOG.md` 条目再动码）。

**用低消耗模型（明确流程/需求）**，同时满足三条：

- 有对应 `AI_docs/DOSSIER/` 模块档案（或主会话在派发单里内联了等价材料）。
- 步骤可枚举到命令级，验收可机器判定（脚本/编译/手动路径明确）。
- 不触碰 `INVARIANTS.md` 高危区与禁改区（改前主会话已核对 `AI_Script/protected-paths.json`）。

**调研型任务默认强档**：需要自主探索、归纳或交叉验证的调研（架构盘点、根因调研、方案对比）是强模型能力；只有当主会话已把"查什么、去哪查、怎么判读"枚举到命令级（检索路径写成一条条可执行的命令），才可降省档。

**判定不了 → 一律升档到强模型**；降档省的钱远小于返工与验收成本。

## 3. 派发纪律

1. **派发判定 = 并行制（唯一规则）**：仅当**同时**满足 ①与主会话当前工作真正独立可并行（无共享文件/状态/前置依赖）；②并行能把总时长压下来、或把质量提升到值得——才派发子任务。否则（线性任务链、共享状态、连续决策、简单任务、需边做边判断）**一律由主会话直接实施**；判定不了 = 不派发，不因"看起来能并行"而拆单。
2. 派发必须用 `TASK_LIST_TEMPLATE.md` 填写派发单，不派"口头任务"；**低消耗模型的派发单必须内联 dossier 片段与入口锚点**，不允许"自己去查路由表"——探索是强模型的能力，不是省档模型的权利。
3. 派发单里写死：机读范围行（`SCOPE:` 行）、独占文件面 + "为什么是这几处"、本任务额外禁止、**不变量 + 卡住时的出口条款**、验收命令、回写要求（缺一不派）。禁改区不在派发单里复述（正典 = 根 `AGENTS.md`，会话自动加载）。
4. 一个派发单绑定一个 `EXECUTION_PLAN.md` §8（当前切片队列）切片，不跨未完成切片。
5. 低消耗模型的改动在验收前**视为未完成**；主会话验收通过才算交付。
6. **范围是分工边界，不是让子任务去猜实现**：派发单只锁"谁此刻能写哪些文件"与"必须满足什么不变量"，不把判断压成没有理由的禁令。子任务回报"按这个范围做不通"时，主会话只有两个正当选择——改单扩范围（重发）或收回自己实施；**不许要求它"想办法在范围内完成"**。

## 4. 交叉验收门（主会话收货 = 一条命令 + 一张清单）

机器门禁：

```powershell
.\AI_Script\verify-scope.ps1          # 范围校验 + 锚点健康 + 文档 lint
.\AI_Script\verify-scope.ps1 -Compile # 追加产品构建+单测+lang 同步（verify.ps1 全量，权威，分钟级）
```

- SCOPE FAIL = 子任务改了禁改区/范围外文件 → 打回，不修不合。
- ANCHORS unresolved > 0 = 锚点失效 → 先修注册表/代码再验收。
- 编译腿以 `AI_Script/verify.ps1` 全绿为准（exit 0）：构建 EDR + NetDiff 31 用例 + lang↔resx 同步 + 坑扫描。

收货清单（每个子任务交付时主会话逐项过）：

1. 机器三绿：`verify-scope.ps1 -Compile -TaskBrief AI_docs/HANDOFFS/<本单>-brief.md` → SCOPE PASS / **TASK SCOPE PASS（改动 ⊆ 本单范围 ∪ 台账面）** / ANCHORS 0 unresolved / LINT 0 error / 编译腿 exit 0。**触发时机**：该子任务有代码改动时跑一次；纯文档/台账交付跑 `verify-scope.ps1`（SCOPE+ANCHORS+LINT）即可；同一 HEAD 的重复编译由日终 `/day-gate` 兜底。
2. `git diff` 逐文件差异审查：范围越界、单一版本被破坏（条件编译/第二读取实现）、UI 文本硬编码、IPC 阻塞、设置写入非原子。
3. 派发单 §F 验收标准逐条勾；向导/模态弹窗等人工路径未跑的标注"未验证风险"，不得记"完成"。
4. 子任务 §H 交付报告齐备；新锚点已进 `AI_Script/code-anchors.json` 且 `refresh-code-index.ps1` 已刷新。
5. 台账回写核对：`PROJECT_STATUS.md`（状态）+ `EXECUTION_PLAN.md` §8（切片队列行）+ 必要的 `DECISION_LOG.md`/`RISK_REGISTER.md`；交接文件落 `AI_docs/HANDOFFS/`。
6. 高风险阶段（读取层/生命周期 IPC/安装链邻近区）追加 peer 只读审查：独立找问题，不看主会话结论。

## 5. 并行会话与写冲突

- **会话交接按任务分文件**：`AI_docs/HANDOFFS/<yyyy-MM-dd>-<task-id>.md`（用 task-list-template 的回写节收尾）；活跃任务指针 = `EXECUTION_PLAN.md` §8 队列的交接文件列。
- 编辑他人 lock 的文件前先在 `EXECUTION_PLAN.md` 队列行认领（lock 列见 `MODULE_REGISTER.md`）。
- 提交拆分：代码与文档可同提交；**不带他人会话的无关修改**。

## 6. 子任务纪律与上下文经济学

- **子任务只吃派发单**：不预读台账、不扩展阅读、不全仓探索（省档禁；材料缺什么回派发单要）。开工三件事：按锚点直达代码入口 → 第一次编辑前写出**可证伪的局部假设 + 最便宜的验证方式** → 完成后只按派发单 §G/§H 回写交回，不扩大范围。**卡住（范围不够、不变量互相冲突、发现派发单事实有误）就停下回报**，不要为了"把活做完"扩范围或绕开约束。
- 任务材料只按 `ROUTING.md` 取对应行；**派发单内联材料优于让子任务全仓检索**。
- 大文件禁整读：超大的生成类文件（参考程序集、二进制产物）一律不读；读文档按路由行精读，旁证检索才用 grep。
